# 资料核对与截图规则

## 证据优先级

实际当前界面与验证结果 > 当前页面实现 > 配套培训文档 > 需求草稿。发生冲突时，描述实际已确认状态；不要把规划中的能力当成已实现能力。

建议 evidence.md 表头：`功能 | 来源位置 | 已验证/文档说明/未验证/异常 | 截图 | 备注`。

## PDF 与 DOCX

- PyMuPDF：`fitz.open(path)`，用 `page.get_text()` 提取，`page.get_pixmap()` 渲染封面、典型正文和截图页。扫描版使用 OCR 后核对原图。
- python-docx：段落、表格都需提取。ZIP 内的 `word/media` 是图片；`word/embeddings` 可能是内嵌 Word、Excel、ZIP 或 OLE 数据包。
- 内嵌 Excel 可用 openpyxl 或解析 XML 读取共享字符串、单元格及公式。核对数值不是只读报告文字。
- OLE 可用 olefile 等专用解析工具读取，不把二进制数据当 UTF-8 打印到工具输出。不自动执行内嵌脚本。
- 将文本与图片的对应关系保留；Word 内的“图片”可能是附件图标而非实际内容。

## 图像处理

- 原图不覆盖，衍生图单独存放；裁剪清除无关留白，不切掉关键按钮和结果。
- 机构标识通用化应包含页面标题、头像/Logo、开场白、会话气泡、页脚、截图中的发布网站名称。
- 去掉方言入口时同步调整相关正文、图注和功能地图。只移除入口，不假称源网站已被修改。
- 多张图并排时按列宽缩放，保持原始比例；禁止拉伸手机屏幕。插图在纸面仍应可读，必要时拆页或放大局部图。
- 等待抽屉、弹窗或动态回答完成再截图；API 请求返回不代表 UI 动画已结束。

## 诚实描述限制

- 无后台访问权：使用培训图并注明来源，不声称已验证发布或保存。
- 模型返回错误：保留错误证据，在常见问题中用通俗语言描述下一步；仅凭异常文本不武断确定根因。
- 业务能力与平台通用控件不同：有附件按钮不代表工作流支持报告识别；有麦克风图标不代表语音端到端可用。
- 通用手册只在与用户操作有关时说明已知限制，不把内部调试流水账变成大段正文。

## 运营分析特别规则

明确区分：记录行数/对话条数、去重会话数、用户数、推荐次数、挂号订单数、实际到院人数。

成功率要写清分子、分母、统计窗口和成功判定。多科室推荐需说明拆分计次方式。覆盖率应以同口径科室清单为分母。

不沿用培训样例中互相矛盾的数字和占位符；无数据写“暂无数据”。症状分类不是医学确诊，咨询量也不代表发病率。
