# PPT制作与模板统一

> 与 `360-ppt-generator`（汇报 PPT 生成）的分工：本技能做**纳米Work 蓝白行业模板**的产品方案和改版，全部原生可编辑；`360-ppt-generator` 做 **360 品牌模板**的文字/海报/混合 PPT，海报模式会调用 AI 生图。用户没指定时，医疗/教育/企业/安全行业的产品方案、智能体宣介用本技能。

## 目标

交付能直接使用的可编辑 `.pptx`，既讲清产品解决问题的业务路径，也符合用户确认的视觉风格。

**内容思路与视觉规范是两套独立依据。** 用户给的产品参考PPT可以指导叙事、业务流程和内容组织，不能因此自动接管字体、背景、Logo、布局和配色。除非用户明确指定新视觉模板，否则始终沿用本 Skill 已确认的纳米Work蓝白行业风格。不能把制作产品方案简化为“把文字放进三张卡片”。

内容方法见 `references/content-playbook.md`，从《医院人事管理系统智能体》和《围术期决策智能体》中提炼。借鉴它们讲业务的方式，不照搬其视觉，也不把其业务能力、指标或部署承诺当成所有产品的默认事实。

**完整产品方案必须包含四个内容模块，不能省略：行业痛点、产品介绍、核心功能、AI介入前后（Before / After）。** 默认按此顺序讲述，再衔接客户价值与落地方式。核心功能必须落实到工作流程；Before / After 必须明确、可辨认地对照同一业务任务，不能仅用价值口号或零散“提效”文案代替。行业痛点必须指向目标行业的具体角色、任务和约束，不泛泛写所有企业都适用的问题。只做单页或仅改格式时按请求范围处理，不擅自扩成整套方案。

先用一句话说明正在做什么，然后直接制作。对“也改一下”“快一点”沿用已有风格，避免重复询问。不要把普通改版扩大为内容重写或数据纠错。仅在关键素材、修改范围确实无法判断时提问；可先完成独立部分。

## 文件与工具

- `references/design-spec.md`：默认模板坐标、字号、颜色、行业判断及常见布局。
- `references/content-playbook.md`：产品方案叙事、单智能体工作流、多智能体协同、前后对比和两份参考材料的结构解析。
- `references/quality.md`：结构保真、内容核对、预览与交付规范。
- `assets/background.png`：蓝白科技背景。
- `assets/logo-{medical,education,enterprise,security}.png`：四行业透明底 Logo，已裁去外部透明边距。
- `assets/cover-medical.png`：医疗行业标准首页背景图。
- `assets/deploy-private.png`、`assets/deploy-cloud.png`：标准部署页插图（院内私有化 / 360 私有云）。
- `scripts/pptkit.py`：可导入的原生PPT绘制工具，提供标准页头、卡片、文字、底栏，以及标准首页 `cover_slide()`、标准部署页 `deployment_slide()`；默认字体微软雅黑。
- `scripts/audit.py`：检查PPT内容、表格、分组、坐标和文件完整性；对比前后文字。
- `scripts/example.py`：生成可编辑的两页演示样例，用于了解工具用法。
- `requirements.txt`：Python依赖。

所有相对路径以本 Skill 所在目录为基准，不依赖用户桌面文件名、历史对话或临时目录。

## 工作流程

### 1. 检查输入

1. 确认输入文件存在，读取页数、页面尺寸、标题、所有文本、表格、分组和图片位置。不要只提取顶层文本；表格和组合图形也可能承载业务信息。
2. 读取 `references/design-spec.md` 和 `references/quality.md`；制作产品方案、补内容或重组逻辑时，必须同时读取 `references/content-playbook.md`。
3. 明确每份输入的用途：待修改内容、内容/流程参考、视觉模板、品牌/图片素材。同一文件可以承担多个角色，但“看看流程思路”只授权参考内容逻辑，不意味着更换视觉。仅对明确指定的视觉模板分析并采用页头、背景、Logo、标题、底栏、字体和卡片。对截图，先识别层级与内容，再按现有风格重建为原生文字和图形。
4. 先核对数据数量、阶段、负责人、价格口径、政策文号等。输入自身不一致时不擅自更改，保留并在交付说明中简短提示实际发现的问题。

### 2. 先组织内容，再选择实施方式

- **只改标准格式**：保留业务文案与流程语义，做视觉统一，不强行加整套产品章节。
- **制作完整产品方案**：先拟逐页内容骨架，默认“首页（`pptkit.cover_slide()` 标准首页）→ 行业痛点 → 产品介绍 → 核心功能与具体工作流 → 协同闭环（适用时）→ AI介入前后 Before / After → 客户价值 → 部署方式（末页，使用 `pptkit.deployment_slide()` 标准部署页）”。可按实际内容拆分页面，不固定页数，但四个必备模块均须覆盖。
- **单页讲解功能**：明确场景/触发、输入、AI工作、人工动作、输出与下游。不能只列“资料解析、智能匹配、风险提示”等抽象能力。
- **多智能体方案**：先解释分工和共享底座，再解释协同顺序、条件分支、回流复评；不能把并行流程画成线性必经步骤。

使用以上内容骨架完成每页的“核心结论、支撑事实、流程/图表、底部价值总结”，然后选择实现方式：

- **仅换 Logo / 少量样式**：局部修改原文件。复杂文稿包含动画、图表、母版、备注时优先直接修改ZIP中的目标XML及关系，避免重建整份文件。按展示顺序解析 `presentation.xml` 的关系，而不是假设文件名序号就是页码。
- **标准化单页 / 简单文稿**：保留原图表、表格、图片和箭头语义，调整头尾及正文位置；用 `python-pptx` 编辑。
- **新建页面 / 需要重排**：使用 `pptkit.py` 构建原生文本、表格、卡片和连线。可复用参考图片，但不得将整页截图当作可编辑PPT交付。

不要对未知文件直接批量按形状索引修改。只有先检查并确认当前输入中的索引含义后，才可针对该文件编写映射。不要通过 `exec` 截取另一个任务脚本来复用函数；导入工具模块。

### 3. 匹配行业 Logo

按整页主题和所属章节判断，而非某个单词：医院临床质量安全属于医疗；学校人才预测属于教育；安全厂商培训属于安全；招聘、门店、营销属于企业。

识别并移除原 Logo 的全部组成部分（图片和拼接文字），然后等比放入新 Logo。不要只替换共享图片资源而误改其他行业页面。混合行业总览保留通用品牌，不强行选一个行业。章节页没有左上角Logo时，不默认添加；业务内容页明显漏Logo时可以补齐。

### 4. 版式制作

1. 首页用 `cover_slide()`，末页用 `deployment_slide()`。正文页建立统一页头与底栏，确定正文可用区域，再布局正文。
2. 全部文字使用微软雅黑（中西文一致）。精简冗余装饰，使用白底、浅蓝边框卡片和蓝/绿/橙分组。正文重要层级清晰、字号足够；长名称先扩大容器或合理换行，再酌情减小字号。
3. 项目矩阵使用原生表格，保留所有状态和百分比。流程图保持箭头方向与闭环关系。路线图按年度或阶段排等宽卡片。全景页保证目录、数量与输入一致。
4. 全家福可使用用户已提供的合适团队图片或已有资产。图片为形象示意，不要求与能力条目人数一一对应；不能把旧14项清单误用为新19项内容。若需要新图，仅在实际有图像生成工具时生成，不能声称生成了未生成的图片。
5. 保存为新文件，名称如 `<原文件名>_模板统一版.pptx`。生成预览前核对正文内容。

### 5. 检查与交付

执行质量检查，见 `references/quality.md`。必要命令：

```bash
python scripts/audit.py 输入.pptx --output 输入审计.json
python scripts/audit.py 修改版.pptx --compare 输入.pptx --output 修改版审计.json
```

对比按文本行的多重集合报告，重新分段、换行或移除旧品牌可能产生差异，必须人工确认。不能仅凭脚本成功就宣称视觉无误。

优先通过实际PPT渲染器（LibreOffice、PowerPoint或可用的系统预览）导出并看图。没有真实渲染器时可输出明确标为“排版示意”的辅助预览；不能称其为PowerPoint实际截图。粗略Pillow绘制会漏掉字体粗细、渐变、表格、圆形和箭头，不能据此判定最终视觉完全正确。

最终回复简短：改了哪些页，PPT下载链接，可选预览链接，以及确实保存的路径。用户通常需要桌面交付时，将最终文件另外复制到桌面；可同时保留工作目录供下载。不要覆盖原件，避免重名覆盖已有修改版。

## 环境准备

优先复用可用环境；缺依赖时创建虚拟环境安装 `requirements.txt`，不要修改系统Python。

```bash
python3 -m venv <临时或工作目录>/ppt-env
<临时或工作目录>/ppt-env/bin/pip install -r <skill目录>/requirements.txt
```

不要派生子代理，除非用户明确要求。独立的输入检查可以并行执行。
