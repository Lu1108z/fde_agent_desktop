# 产品方案PPT：内容与业务流程方法

## 使用边界

本方法来自用户明确指定的两份内容参考：
- 《医院人事管理系统智能体》：12页，多场景产品方案。
- 《围术期决策智能体》：10页，围绕同一患者的专业协同方案。

参考的是叙事顺序、流程粒度、角色分工与价值表达。视觉由 `design-spec.md` 和现有品牌素材负责；不继承参考文稿的字体、Logo位置、截图外框、装饰或页面密度。参考内容不等于对新产品的事实授权。

## 一、先回答客户的问题

### 用户确认的必备模块

完整产品方案必须覆盖，默认顺序如下：

1. **行业痛点**：行业背景下谁在什么任务上遇到什么阻碍，造成什么影响，需要解决什么。
2. **产品介绍**：产品是什么、服务谁、解决哪些痛点、由哪些智能体构成、当前覆盖边界。
3. **核心功能**：每项功能的真实业务场景、输入、AI动作、人工动作、工作流程和输出成果。
4. **AI介入前后（Before / After）**：明确展示同一任务原来的做法与引入AI后的做法、角色变化、输出变化和实际收益。

再补客户价值及部署/落地方式，多智能体产品补协同闭环。可合页、可多页，不要求固定页数；不能省略必备内容或以其他章节代替。单页制作与纯格式调整按用户指定范围执行。

一份产品方案应逐步回答：
1. 这是什么产品，为谁服务，当前边界是什么？
2. 客户现在怎样工作，难在哪里，为什么值得改变？
3. 哪些智能体分别解决哪些问题，依赖什么数据？
4. 实际业务中何时触发、输入什么、AI做什么、人做什么？
5. 输出交给谁，怎样进入下一步，出现变化怎样回流？
6. 与原有工作方式相比，具体改变了什么？
7. 客户得到哪些可解释的价值，如何落地？

先说明业务，再解释AI。一个页面聚焦一个结论；标题说清主题，副标题交代场景或判断，正文提供过程与证据，底栏总结本页价值。

## 二、完整方案的推荐结构

按产品复杂度调整页数；行业痛点、产品介绍、核心功能及Before / After为必选，其余模块按任务选择：

| 模块 | 内容任务 | 表现方式 |
|---|---|---|
| 封面（首页，固定） | 产品名和一句价值定位 | 标准首页：场景背景、居中大Logo、产品名、标语，`cover_slide()` |
| 客户现状 | 当前角色、系统、材料和工作方式 | 现状结构或真实业务场景 |
| 行业痛点（必选） | 把行业现状转成具体业务问题和需求 | 角色/任务→问题→影响→需求，3–4组为宜 |
| 产品介绍（必选） | 面向谁、解决什么、业务边界、模块分工 | 一段精炼定义＋模块关系图 |
| 智能体架构 | 谁负责什么、共享什么、产出什么 | 数据底座→业务智能体→业务输出 |
| 核心功能与单智能体详解（必选） | 在真实场景中如何运转 | 场景、具体动作、工作流、输出成果 |
| 协同闭环 | 多角色/多智能体如何衔接 | 主链＋条件分支＋变化回流 |
| AI介入前后 Before / After（必选） | 同一业务任务的工作方式变化 | 场景／Before／After／变化价值 |
| 客户价值 | 从具体动作推导客户收益 | 3–5类价值及依据，指标注明属性 |
| 部署方式（末页，固定） | 院内私有化部署 / 360 私有云订阅模式 | 标准部署页，左右两卡四维对照 |

现状与痛点可以合页，产品介绍与能力总览可以合页。参考材料原顺序可以研究，但最终默认先讲行业痛点，再讲产品及解决方式。Before / After优先有独立对照页；短方案合页时也必须有明确的Before / After区域。只做单页时选对应结构，不补无关章节。

## 三、两份参考的具体思路

### A. 医院人事管理系统：从分散事务到人才管理体系

叙事顺序：
封面 → 产品定义与核心能力 → 客户现状 → 四类痛点 → 四个智能体及底座关系 → 四个单体功能/工作流 → 有无智能体对比 → 医院价值 → 部署方式。

值得继承：
- 产品定义明确服务人事部门，覆盖考核、引才、招聘与基础资料治理。
- 总览同时展示**业务输出、业务智能体、基础库**，让客户看懂模块关系，不只是四个并列名称。
- 每个功能页都有具体动作、顺序和成果。中层干部考核：岗位职责 → AI起草OKR、人工确认 → 工作记录与成果 → AI核验 → 审核评价与案例沉淀。
- 高端人才库从科主任需求进入，发现线索、形成画像、匹配、人工寻访与持续跟进。名单输出不等于完成引才。
- 人事工作流区分招聘和人员配置两条路径：JD/简历→AI排序→HR复核→面试入职；人员结构数据→梯队缺口分析→风险提示→补员培养。不能硬连成一条线。
- 基础库把上传、提取清洗、人工确认、到期提醒/材料导出讲清，体现数据维护与调用。
- 对比表按考核、引才、简历筛选、梯队、基础数据等具体任务展开；医院价值与这些任务逐项呼应。

避免照搬：参考中的“2000封简历”是该页的场景描述，不能成为所有产品的默认处理能力；任何模糊措辞或疑似错字都应核实，不作为标准术语保存。

### B. 围术期决策：围绕同一患者把判断接到落实

叙事顺序：
封面 → 三个术前智能体与边界 → 院方痛点 → 手术评估 → 术前MDT → 麻醉评估 → 协同闭环 → 医院价值 → 传统/智能体对比 → 部署方式。

值得继承：
- 先说明围术期涵盖术前术中术后，但初期方案聚焦术前的三个智能体，避免把远期方向讲成已覆盖范围。
- 单体页按业务时点组织，而不是列技术名词。例如麻醉评估分申请后初评、高危访视、新变化复评。
- 每个场景讲“现在的问题 → 引入后工作方式 → 直接收益”。如分散病史需人工翻查 → 聚合患者画像并定位待核实问题 → 带着问题访视。
- MDT是会前备材、会中辅助真实讨论、会后记录与落实；AI整理不等于专家已经完成会诊。
- 主链：患者画像与手术评估 → 申请前核验 → 下达手术申请 → 麻醉评估与访视 → 术前准备落实 → 术前复核。
- MDT按指征介入，可支撑外科与麻醉，不是所有病例必须通过的固定串行节点。
- 病情、检查、用药或术式变化触发画像更新与相关专业复评，体现真实回流。
- 价值页分重大风险前移、核心制度落实、手术资源效率。参考中列出的百分比标为“建设目标”，不是已验证成果；迁移到新产品时必须有相应来源。

## 四、单智能体页的内容模型

生成文案前先填写以下字段；源材料没有的事实不编造：

```text
服务对象：谁在用？
场景/触发：在哪个业务时点需要它？
原有方式：今天怎样做，卡在哪里？
输入依据：已有文件、记录、数据、规则是什么？
AI动作：解析、对照、汇总、匹配、提示、起草等具体动作。
人员动作：谁确认、补齐、评审、访视、执行或作最终决定？
输出成果：名单、画像、记录草稿、核验提示、计划、任务等。
下游衔接：交给谁、进入哪个节点？
变化回流：什么变化触发更新或复评？适用时填写。
客户收益：上述动作直接改善什么，不夸大为保证。
```

内容较多时拆成“核心场景页”和“工作流页”。不要用10pt文字挤进一页。可采用：
- 上方3个场景卡，下方4–6步工作流和输出成果；
- 左侧产品/场景图，右侧3组“现在→引入后→收益”；
- 两条业务泳道，末端标明输出和责任人。

保留统一页头、字体和底栏，正文结构应由内容决定，而不是每页都画同样的三列卡片。

## 五、前后对比与价值表达

完整方案中本节必选。页面标题推荐“AI介入前后：业务工作方式的变化”，对照列明确标为“Before｜AI介入前”和“After｜AI介入后”，按当前产品选择3–5个代表场景。每行包括：

| 业务场景 | Before｜AI介入前 | After｜AI介入后 | 变化与价值 |
|---|---|---|---|
| 同一个具体任务 | 谁手工做什么、有哪些困难 | AI承担哪些动作、人保留哪些动作、形成什么成果 | 可由流程推出的具体改善 |

对比要体现工作流与交付物变化，不只是把原有功能加上“智能”二字。即使功能页已写“现在/引入后”，也要确保方案有完整、明确的Before / After对照，不能让用户自行拼凑。

比较同一个业务维度，双方描述粒度一致：
- 弱：传统效率低／AI效率高。
- 好：人工逐份阅读并对照岗位要求／批量匹配JD、给出依据，HR复核后推进面试。
- 弱：传统只能记录／AI全自动决策。
- 好：资料分散、判断需人工拼接／聚合画像、提示冲突与依据，相关专业确认。

价值要能回指前面的功能或流程。例如“减少临时补录”应有前置核验，“经验可复用”应有审核与归档，“持续改进”应有反馈与版本更新。无来源时不补提升百分比，不把目标写成业绩。

## 六、部署页与事实边界

完整方案最后一页固定为标准部署页：院内私有化部署与 360 私有云订阅模式，左右两卡，按部署位置、数据处理、运行方式、医院侧条件四维对照。版式与默认口径见 `design-spec.md` 的“标准部署页”，用 `pptkit.deployment_slide()` 生成。落地准备、实施步骤等内容如需呈现，放在部署页之前单独成页，不挤进部署页。产品资料对某一维度另有约定时只替换该项文字并在交付时提示。

## 七、内容验收

- **四项强制检查**：行业痛点、产品介绍、核心功能、Before / After都已呈现；少任何一项，完整产品方案不得视为完成。
- Before / After左右对应同一场景，明确AI与人的分工、输出变化，不用笼统价值口号冒充对照。

- 产品是什么、当前做什么、暂未做什么在相关范围页表达准确。
- 痛点与能力对应，能力与输出对应，输出与客户价值对应。
- 所有流程有输入、动作和输出，必要角色和确认节点完整。
- 顺序、并行、条件介入、回流四类关系区分明确。
- AI产出草稿、名单或建议与业务完成状态没有混淆。
- 案例、建设目标、已实现结果标记准确，不复制参考产品的数字承诺。
- 内容参考只影响叙事方法，最终视觉仍符合现有蓝白模板。
