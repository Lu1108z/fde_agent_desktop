# FDE 阶段一：数据流程图

画数据怎么进入 SDR、怎么到达智能体。结构固定，每个项目只替换内容。文件 `stage1/data-flow.md`。

## 铁律
- 智能体只通过 SDR 取数，**任何连线都不能让智能体直连医院系统**。
- 有 CDR 就让 SDR 从 CDR 抽取；没有 CDR 就由 SDR 逐个对接业务系统。
- 数据不出内网，只出结果。SDR 部署在内网，以只读 View 取数，主动出站；**没有任何连线从外网指向内网**。

## 固定章节（标题保持一致，便于局部重新生成）
## 一、文件头
项目、版本（首版 v0.1）、日期、编写人、资料来源清单。
## 二、CDR 判断
有 / 无 / 未知，附依据；未知时给 Q 编号。有 CDR 时列出它覆盖了哪些系统。
## 三、数据流程图
一个 ```mermaid 代码块（flowchart LR）。
## 四、系统清单
表格：编号 | 系统（标准名） | 厂商 | 主要数据域 | 接入方式 | 可信度 | 风险 | 应向谁确认
## 五、接入风险
表格：风险 | 关联系统 | 影响 | 应对建议
## 六、待确认事项
表格：编号 | 问题 | 关联系统 | 应向谁确认

## 固定分层（从左到右）
1. 数据源层：每个系统一个节点，写 `S-xx 名称`、厂商、接入方式。
2. CDR（可选）：用 `{{CDR：有/无/未知}}` 表示。
3. SDR 数据底座：一个 `subgraph`，内含三层，名称固定：数据治理层（清洗 · 映射标准数据）→ 服务平台层（脱敏 · 审计）→ 服务网关层（MCP / HTTP · TLS），不展开内部组件。
4. 智能体：写本项目涉及的智能体名称，不确定时写场景。

## 必须标出
- 网络边界：`subgraph IN[医院内网 · 业务网]` 把数据源层、CDR、SDR 框在里面。
- 接入方式四选一：只读 View / 接口 / 文件导入 / 从 CDR 抽取；不知道写「待确认」+ Q 编号。
- 每条连线写传的数据域（只用下方数据域词表）。
- SDR 到智能体的连线固定写 `==>|只出结果 · 主动出站|`。
- 风险点（接不通、不开放、厂商不配合）用 `:::pain` 节点挂到对应系统。
- 图开头固定声明 `classDef guess stroke-dasharray:5 4,stroke:#c27a1e` 与 `classDef pain stroke:#c27a1e,stroke-width:2px`；AI 推测或待确认的系统和连线用 `:::guess` / `-.->`。

## 词表
- 系统标准名：HIS、EMR、LIS、PACS/RIS、手麻系统、护理系统、HRP/HR 系统、CDR、线下文件（Excel、纸质台账，接入方式只能是文件导入）。
- SDR 数据域（暂定 14 个）：患者主索引、就诊、诊断、医嘱、检验、检查、手术麻醉、护理、药品、费用、设备物资、组织科室、人员、排班考勤。不能自造。

## 编号
- 系统 `S-01` 起，一个系统在整个项目里只有一个编号，《业务流转图》《数据需求清单》沿用。
- 待确认问题 `Q-xx` 与 `.fde-flow/context.json` 的待确认事项共用一个序列。

## 规则
- 只做到系统和数据类别层，不写字段、表名、SQL、脱敏配置。
- 资料不全照常出图，缺口转成待确认。可信度：已确认 / 资料 / 推测 / 待确认，推测不画实线。
