# FDE 阶段一：数据需求清单

两张图看流向，这张表用来逐项确认。文件 `stage1/data-requirements.md`。

## 固定章节（标题保持一致，便于局部重新生成）
## 一、文件头
项目、版本（首版 v0.1）、日期、编写人、资料来源清单。
## 二、智能体场景
表格：场景 | 智能体要做的事 | 关联业务节点（P 编号）
## 三、数据需求清单
主表，列固定如下。
## 四、待确认事项
表格：编号 | 问题 | 关联数据项 | 应向谁确认

## 主表列
编号 | 用途/智能体场景 | SDR 数据域 | 数据内容 | 可能来源系统 | 接入方式 | 可信度 | 敏感级别（初判） | 确认人/待确认编号 | 更新频率

必填：编号、用途、SDR 数据域、数据内容、可能来源系统、接入方式、可信度。
- 编号 `D-01` 起，全程不变；作废的标「作废」，不删除。
- SDR 数据域只能从词表选：患者主索引、就诊、诊断、医嘱、检验、检查、手术麻醉、护理、药品、费用、设备物资、组织科室、人员、排班考勤。
- 数据内容举 3～5 个关键内容（例「工号、科室、职称、班次」），**不写字段名**。
- 来源系统填《数据流程图》的 `S-xx`；不知道写「待确认」。
- 接入方式：只读 View / 接口 / 文件导入 / 从 CDR 抽取 / 待确认。
- 可信度：已确认 / 资料 / 推测 / 待确认，附依据或 Q 编号。
- 含患者身份或个人隐私的，敏感级别标「敏感」；正式分级在 SDR 配置时确定。
- 更新频率选填：实时 / 每日 / 每月。

## 与后续阶段的对应（后续只补列，不改已有内容）

## 规则
- 智能体用到的每类数据都要有一行。
- 智能体只通过 SDR 取数，不写直连业务库的接入方式。
- 资料不全照常产出，缺口转成待确认，`Q-xx` 与 `.fde-flow/context.json` 待确认事项共用一个序列。
