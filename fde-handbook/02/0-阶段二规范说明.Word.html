阶段二 · 需求沟通-原型设计——规范说明

这个阶段干什么：带着阶段一备好的话术进场，跟客户做结构化需求沟通——第一轮先启动、摸清组织关系，再一轮轮把需求聊透，整成《需求与数据对接确认表》和《AI需求能力清单》。再用这两份喂智能体做出能看能点的产品原型 Demo，用原型把需求收敛对齐。

一条主线：第一轮启动+摸组织关系 → 多轮沟通挖需求、对齐AI能力 → 出原型 → 拿原型收敛需求 → 交棒阶段三签字定稿。

文档分两类：带 📖【知识】的是要学会内化的方法；带 📝【交付】的是每个项目现场要填、要产出的模板。

一、文档清单与用法

一句话：学会【知识】一件（产品原型设计规范），交出【交付】三件（对接确认表、AI需求能力清单、产品原型Demo）。

# 文档 类型 怎么用
1 产品原型设计规范 📖【知识】 学会怎么用智能体——用【FDE专属】产品设计专家出 PRD + 原型，人工把质量关
2 需求与数据对接确认表（含组织关系） 📝【交付】 每轮沟通填一份——第一轮摸组织关系+启动，逐轮挖需求、对数据源。是沟通初稿，喂智能体做原型用
3 AI需求能力清单 📝【交付】 把客户要的AI能力单独列一份——能力总览 + 每个能力的输入/输出/效果指标/验收口径/异常处理
4 产品原型Demo 📝【交付】 出可交互原型 + PRD，带去演示，用"能看能点的东西"把需求收敛对齐

二、标准动作流程

阶段一交棒（备弹练熟，进场）
│
① 第一轮启动 → 填【交付】2 对接确认表·第一轮
（甲方组织启动、摸清组织关系五层人、对齐本次议题；组织关系并进这张表）
│
② 多轮挖需求 → 逐轮填对接确认表（第二轮/第三轮）
（抠细节、对数据源就绪度、逐条聊需求；每轮当场发群对齐）
│
③ 列AI能力 → 填【交付】3 AI需求能力清单
（客户要的AI能力逐条列出，定效果指标和验收口径）
│
④ 出原型 → 用【知识】1 的【FDE专属】产品设计专家智能体
（喂对接确认表+AI能力清单 → 智能体出 PRD + 可交互原型 → 人工过质量关）
│
⑤ 拿原型收敛需求 → 带 demo 找代理商/客户演示
（用能看能点的原型对齐方向、把需求磨清磨收敛，迭代到方向认可）
│
▼ 原型认可、需求基本收敛 → 交棒阶段三签字定稿需求 + 做智能体设计

逐步解释

  • 第一步 · 第一轮启动（填对接确认表·第一轮）：进场第一轮，甲方组织把项目启动起来，当场摸清组织关系——五层人(院长/总经理→分管副总→部门主任→操作员→信息科)谁拍板、谁负责、谁配合数据。组织关系直接填进对接确认表的"二、组织关系"。第一轮相当于启动会，把人对齐了才好往下聊。
  • 第二步 · 多轮挖需求（逐轮填对接确认表）：第二、三轮抠细节、对数据源就绪度、逐条把需求聊透。每轮沟通当场发群对齐。注意：对接确认表是沟通初稿、分轮填，不是签死的需求——真正签字定死是阶段三的事。
  • 第三步 · 列AI需求能力清单（填【交付】3）：把客户要的AI能力单独整成一份清单——每个能力做什么、关联哪条需求、效果指标(如"问数≤30秒/准确率≥95%")、验收口径、异常怎么处理。这份是喂智能体做原型、也是后面智能体设计的重要输入。
  • 第四步 · 出产品方案与原型（学【知识】1，用统一智能体做）：把对接确认表 + AI需求能力清单喂进【FDE专属】产品设计专家智能体，它内部自动跑结构化拆解、PRD三层、信息架构、六区块生成，约 3 小时出一版可交互原型。
  • 第五步 · 拿原型收敛需求：原型带去找代理商/客户演示。原型是收敛需求的工具——很多说不清的需求，客户看到能点的东西才反应过来"对/不对"。 方向认可、需求基本清楚了，交棒阶段三签字定稿。

三、本阶段节奏与卡点

这里是 2+1 的主场。 一轮 ＝ 3 次 ＝ 2 次需求对接 + 1 次当轮确认签字并出原型，一整轮在本阶段跑完。按次数算，不按天卡：顺的话大约一天一轮、当天发群对齐，但遇上加时赛天数会乱、次数不变。需求大就多跑几轮，即（2+1）× n。

  • 第 1 次对接：启动 + 摸清组织关系五层人 + 对齐议题
  • 第 2 次对接：抠细节、对数据源、把需求聊透
  • 第 3 次 · 确认签字 + 出原型：当轮需求群里确认签字，拿对接确认表喂智能体出原型、用原型收敛

这里的“签字”是每轮当轮确认（群确认等同签字）；阶段三还会把收敛后的需求上《需求最终确认表》总签定死——两层，别混。

环境线（并行）：聊需求靠人，不等环境；同时信息科那边推进进场、部署基础服务——两条线各走各的，环境慢不该拖住需求。

加时卡点：① 约不到人、甲方不配合沟通；② 当轮需求确认签不了字（群里迟迟不拍板）——签不了就进加时。一进加时先发邮件告知甲方（写清卡在哪、在等什么），留痕防扯皮；等待时间算「加时周期」，暂停计时、单独记。细则见 FDE项目推进节奏机制。

四、四条铁律

  1. 第一轮先启动、先摸组织关系——人没对齐就往下聊，聊到验收才发现拍板人是另一个，方向全返工。第一轮把五层人摸清、议题对齐。
  2. 原型驱动需求收敛——需求聊得再多也难一次说清，拿对接确认表快速出原型，用能看能点的东西一轮轮磨收敛，别指望上来就签死。
  3. 原型统一用【FDE专属】产品设计专家——别散着拼提示词，智能体出的交付物才标准、可复制。
  4. AI能力要量化、可验收——AI需求能力清单每条都定效果指标和验收口径，不写"好用""智能"，写"≤30秒""准确率≥95%"。

五、这个阶段的产出物

产出物 说明
需求与数据对接确认表（含组织关系） 分轮填的沟通产物，第一轮含组织关系，喂智能体做原型用
AI需求能力清单 客户要的AI能力逐条列出，带效果指标和验收口径
可交互原型 + PRD 能点能看的原型 + 三层PRD，方向经业务方认可

六、做到什么算过关（阶段级自检清单）

  • 第一轮摸清组织关系，五层人到齐、拍板人明确
  • 需求逐轮聊透，整进对接确认表（沟通初稿）
  • AI需求能力清单每条定了效果指标和验收口径
  • 可交互原型出来了，能点能看，业务方认可方向没跑偏
  • PRD 三层分层清晰，功能可追溯到需求
  • 原型带 demo 演示过，需求基本收敛对齐

全打勾，才算产品原型做扎实，可以交棒阶段三签字定稿需求 + 做智能体设计。
