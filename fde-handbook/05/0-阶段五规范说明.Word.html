一、阶段概况

本阶段目标是在已有可运行行业工作台系统基础上，通过客户真实试用与三轮迭代打磨，完成从"能跑"到"定稿成型"的产品转化，并沉淀可复制的行业模板。核心主线有两条：一是把智能体在真实业务里跑稳、跑准、跑出价值；二是建立一套"客户反馈—团队响应"的闭环机制，让每条反馈都有归属、有动作、有闭环。下表为本阶段关键要素概览。

要素 内容
阶段名称 阶段五：客户试用 + 智能体优化
阶段目标 打磨稳定可复制的行业方案，形成定稿产品 + 行业模板
负责人 倪梓潇、胡瀚文
输入 能跑的行业工作台系统、客户试用渠道
输出 试用反馈汇总表、三轮迭代记录、定稿的成型产品、可复制行业模板、项目交付签字表
参与角色 FDE项目经理 + 客户（试用方）
建议周期 2–4 周 / 三轮迭代
成功标准 试用满意度高，问题闭环，智能体准确率达标

二、三轮定稿计划

本阶段采用三轮递进式定稿：第一轮看大方向，第二轮抠细节，第三轮定死。每轮聚焦不同重点，逐步收敛至可上线版本。三轮之间不是简单重复，而是问题粒度从粗到细、验收标准从松到严的收敛过程。

轮次 阶段定位 核心任务 反馈分类与动作
第一轮 看大方向 验证核心流程与价值、检查关键功能完整性、明确优先级与范围 功能缺失 → 调整迭代计划
第二轮 抠细节 优化业务逻辑与规则、完善数据与字段定义、修复问题与边界场景 逻辑不通 → 改流程
第三轮 定死 确认体验与交互细节、全量验证与回归测试、锁定版本与定稿上线 体验问题 → 调交互

三、客户反馈机制（客户怎么反馈）

客户试用过程中产生的反馈是本阶段最核心的输入。反馈不能散落在聊天记录里，必须被结构化地收集、归类、流转。我们设计"四渠道 + 一张表"的收集方式，确保反馈不丢、不漏、可追溯。

3.1 反馈收集渠道

渠道 适用场景 收集方式 责任人
现场陪跑 上线当天及头 3 天高频问题 产品同学现场记录，当天录入反馈表 FDE项目经理
微信&推推答疑群 试用期内日常疑问、偶发问题 群内接单，工单化登记（问题/处理人/耗时） 答疑值班人
埋点异常告警 客户没说但系统先暴露的问题 后台监控调用失败、超时、空结果，主动列入 数据/平台同学
周度复盘会 试用一周后的集中性、趋势性问题 客户口述 + 我们演示复现，会议纪要入表 FDE项目经理

3.2 反馈分类标准

所有反馈按问题性质分为三类，分别映射到不同的处理动作与负责人，确保每条反馈都有归属、有动作、有闭环。

反馈类型 问题特征 处理动作 处理方
功能缺失 产品方向、优先级、范围与预期不符 调整迭代计划，重新对齐范围与排期 FDE项目经理
逻辑不通 业务逻辑、字段定义、规则不通或缺失 改流程，完善业务规则与数据定义 FDE项目经理 + 客户确认
体验问题 交互细节、操作流畅度、视觉与反馈 调交互，优化体验与交互细节 FDE项目经理

3.3 反馈闭环要求

每条反馈必须走完"登记 → 分类 → 响应 → 验证 → 归档"五步，缺一不可。反馈表统一字段：编号、来源渠道、反馈人、反馈时间、问题现象、分类、处理动作、负责人、状态、闭环时间、验证结论。未闭环的反馈在每日站会过一遍，超 48 小时未响应自动升级到负责人。

四、我们如何应对（响应机制）

收得到反馈只是第一步，能不能快速、准确地响应，决定客户对产品的信心。我们的响应机制按"分级 + 时效 + 复现"三条线展开。

4.1 响应分级与时效

级别 判定标准 响应时效 处理方式
P0 阻断 核心流程跑不通、结果大面积错 30 分钟内响应，当天修复 立即拉群，hotfix 走绿色通道
P1 重要 单点功能错、特定场景结果偏差 4 小时内响应，本轮内修复 进当轮迭代计划，指定负责人
P2 一般 体验瑕疵、文案、非关键提示 24 小时内响应，下轮统一处理 进待办池，下周排期
P3 建议 客户提出的优化建议、新需求 一周内回复评估结论 评估是否纳入二期

4.2 响应动作三件套

每条 P0/P1 反馈的响应必须包含三件事，缺一件视为未闭环：

  1. 复现定位：用 Trace 拉全链路日志，区分是智能体理解错 / 工具调用错 / 数据脏 / 流程缺，给出根因，不能凭感觉改。
  2. 最小改动：定位到具体环节后做最小改动（改 1 句 Prompt、补 1 条规则、修 1 个字段映射），改完跑评测集对照，禁止大改牵连。
  3. 客户回执：改完主动回到反馈渠道告诉客户"已修复 + 改了什么 + 怎么验证"，让客户感知到闭环，而不是默默上线。

4.3 响应防呆

  • 每条反馈必须在反馈表里写明根因，禁止只写"已处理"。
  • 改 Prompt / 规则必须留 A/B 对照数据（改前 vs 改后准确率），数据入档。
  • 同一类问题反复出现（≥3 次）触发专项复盘，挖共因，不能每次都打补丁。

五、智能体优化（核心）

智能体优化是本阶段的技术主线。优化不是玄学调 Prompt，而是"问题定位 → 口径对齐 → 最小改动 → 对照验证 → 兜底补强 → 沉淀复用"的工程化闭环。以下以四院心内科归因智能体为样板，每条能力都对应一个能照着干的动作和能看见的产出。

5.1 使用侧能力（先确认"真有人用"）

实例： 7/22 上线，当天主任亲手跑通 1 次归因；7/22–8/21 共 30 天，后台埋点显示真实发起归因 184 次、日均 6.1 次，剔除 2 个只登不点的护士号后真实活跃率 78%。

使用侧能力 怎么干 能看见的东西
现场交底 上线当天拉使用人当面跑一遍 交底签到表 + 主任亲手跑通 1 次归因
使用埋点看数 后台统计调用次数、最常查的亚专业、只登不点账号 30 天活跃率报表（真实调用比例）
答疑通道 建企微群，头 30 天卡住能找到人 答疑工单表（问题 / 处理人 / 耗时）
判真假使用 剔除"只登不用"账号，算真实活跃 失活账号清单 + 剔除后真实活跃率

5.2 优化侧能力（让智能体越用越准）

实例： 7/25 收到"药占比对不上"反馈 → Trace 回放定位到 Prompt 定义句错 → 改 1 句 + 补 1 条兜底 → 10 病例 A/B 准确率 72%→91% → 沉淀成 Playbook 片段入库。

优化侧能力 怎么干 例子 / 结果
Trace 回放定位 拉全链路日志，区分是智能体理解错 / 工具调用错 / 数据脏 药占比对不上 → 定位到 Prompt 定义句错
业务口径对齐 找客户确认指标定义，写进确认单 药占比 = 药费/总收入，非药品收入占比
改 Prompt 改定义句 + 计算公式 改 1 句
A/B 对照 改前 / 改后跑评测集对比 10 病例准确率 72%→91%
异常兜底补强 补数据缺失 / 超时 / 歧义分支 药品收入缺失时标注"数据不全"不硬算
沉淀复用 抽成 skill / Playbook 入库 "药占比定义句"片段，下个医院直接用

5.3 优化优先级

当反馈同时涌入时，按"影响面 × 准确率损失"排序，优先改影响面大且拉低准确率的问题。单纯体验类问题让位给结果准确性问题——结果错是硬伤，体验差是软伤，先保硬伤。

六、支撑工具

本阶段依托三类工具协同推进，分别覆盖迭代执行、客户反馈与行为追踪，形成从发版到验证到优化的闭环。

工具 定位 核心能力 用途
产品迭代技能 迭代执行 需求管理、版本规划、迭代执行 支撑三轮定稿的版本与计划管理
客户反馈渠道 试用与反馈 客户试用、反馈收集、问题跟踪 组织试用并汇聚反馈汇总表
Trace 全链路追踪 行为追踪 行为追踪、问题定位、数据驱动优化 定位真实使用问题，驱动优化决策

七、30/60/90 使用率盯防

验收通过只代表"当时能跑"，30 天使用率才代表"真有人用"。上线后设三个复盘点主动回访，使用率掉了早点回去补。

复盘点 看什么 动作
30 天 刚上线，抓小问题 答疑通道收口，小问题即修
60 天 看真在不在用 真实活跃率，掉了一线回访找原因
90 天 看新需求看留存 收新需求评估二期，留存低复盘是否好用

八、可复制行业模板（方法通用·结果定制）

三轮定稿跑通后，把可复用的部分打包成行业模板，下个行业直接套，只换行业定制部分。

分类 内容
不换（通用方法） 四步标准法、五层拆解法、三轮定稿机制、需求交流模板、平台还原方法
要换（行业定制） 拓客经验和业务知识、业务场景重新拆、ER 模型、数据源、行业 skill、知识库

九、阶段交付与计分卡关联

本阶段产出直接关系五维计分卡两大块——30 天使用率(25%)和产品化贡献(15%)，试用不是走过场。

计分卡维度 权重 本阶段对应动作
30 天使用率 25% 埋点看真实活跃，30/60/90 盯防
产品化贡献 15% 沉淀可复制模板（skill 包 + 知识库 + ER + UI）
验收通过率 25% 三轮定稿后一次验收通过、不含返工
交付效率 20% 2–4 周内完成三轮定稿
知识沉淀 15% 反馈/迭代记录/异常案例归档入库

十、阶段总结

本阶段以"客户试用 + 智能体优化"为主线，2–4 周内完成三轮定稿。第一轮聚焦核心流程与方向对齐，第二轮聚焦业务逻辑与字段细节，第三轮聚焦体验与回归并锁定版本。客户反馈通过"现场陪跑、企微答疑、埋点告警、周度复盘"四渠道汇入统一反馈表，按方向 / 流程 / 体验三类分流，走完"登记→分类→响应→验证→归档"闭环；团队响应按 P0–P3 四级定时效，每条 P0/P1 必须做到"复现定位 + 最小改动 + 客户回执"三件套。智能体优化以四院归因为具象样板：使用侧抓现场交底、埋点看数、答疑通道、判真假使用；优化侧用 Trace 定位、业务口径对齐、改 Prompt、A/B 对照、异常兜底补强、沉淀复用，按"影响面 × 准确率损失"排优先级。上线后按 30/60/90 天盯使用率，跑通后打包可复制行业模板（方法通用、结果定制）。阶段交付：定稿的成型产品 + 可复制行业模板 + 三轮迭代记录，直接关系五维计分卡中 30 天使用率(25%)与产品化贡献(15%)两大块，达成试用满意度高、问题闭环、智能体准确率达标即视为阶段完成。
