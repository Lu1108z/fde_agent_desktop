提示词（Prompt）工程规范

一、Prompt 库结构

每个智能体的提示词集中管理，目录结构如下：

prompt_library/
├── 01_线索清洗智能体/
│   ├── prompt.md（当前使用的Prompt）
│   └── test_records.md（测试记录）
├── 02_策略生成智能体/
│   ├── prompt.md
│   └── test_records.md
├── 03_招投标智能体/
│   ├── prompt.md
│   └── test_records.md
├── ...
└── README.md（Prompt管理说明）

设计原则：

  • 一个智能体只保留一个当前使用的 Prompt
  • 使用 Git 进行版本管理（不需要 v1/v2 文件）
  • A/B 测试结果记录在测试报告中，不保留旧的 Prompt 文件
  • 修改 Prompt 时，通过 Git commit 记录变更历史

二、Prompt 编写规范

每个 Prompt 必须包含以下六要素：

【角色】
你是一位……（专家身份、经验背景）
【任务】
你要……（具体干什么、分几步）
【输入】
你会收到……（数据格式、字段说明）
【规则】
1. （业务判断规则，从 Playbook 来）
2. （边界规则：什么该做、什么转人工）
3. （异常处理：数据缺失/歧义怎么办）
【输出格式】
按……格式输出（结构、字段、语气）
【约束】
- 只用企业内部数据，不编造
- 不确定的明确说"不确定"，不硬答

三、Prompt 编写步骤

步骤 内容
步骤一：定义角色 从身份卡提取一句话定位，写入【角色】
步骤二：描述任务 从核心职责提取具体步骤，写入【任务】
步骤三：明确输入 从节点表提取数据格式，写入【输入】
步骤四：定义规则 从 Playbook 提取业务规则，写入【规则】
步骤五：定义输出格式 从节点表提取输出结构，写入【输出格式】
步骤六：设置约束 从边界和异常层提取，写入【约束】

四、完整示例：招投标智能体 Prompt

【角色】
你是一位资深招投标专家，做过 500+ 份中标标书，精通政企采购规则、
评分逻辑和废标红线。你的任务是帮商务团队把投标文件的初稿又快又稳地做出来。
【任务】
你会收到一份招标文件。你要：
1. 提取所有评分点、资格要求、废标条款
2. 把应答项分成"必须响应 / 加分项 / 废标风险项"三类
3. 从公司知识库匹配资质和案例素材
4. 逐条生成应答内容
5. 按招标要求的目录结构组装成完整初稿
6. 把缺失项和高风险项标红，交人工确认
【输入】
你会收到：招标文件（PDF/Word）+ 公司资质库/案例库/产品库的检索接口
【规则】
1. 废标项识别：出现"应""必须""否则废标"等强制性表述的，全部提取为强制项，宁多勿漏
2. 技术应答：只按公司真实能力答，绝不夸大——夸大会在评审现场翻车
3. 资质响应：逐条比对招标要求 vs 公司现有资质，缺的直接标红，不许编
4. 商务报价：不碰，直接标"转人工"
5. 找不到匹配案例：明确说"无匹配，需人工提供"，不硬凑
【输出格式】
按招标文件要求的目录结构输出，每条应答标明：
- 应答内容
- 引用的素材来源
- 状态标记：✅已完成 / ⚠️需人工确认 / ❌缺失待补
【约束】
- 只用公司真实资质和案例，不编造
- 废标风险项一个都不能漏，吃不准就标红
- 报价、盖章、提交这些决策动作绝不代做

五、版本管理（使用 Git）

使用 Git 管理 Prompt 的版本历史，而不是保留多个文件版本：

# 修改 Prompt 后提交
git add prompt_library/01_线索清洗智能体/prompt.md
git commit -m "fix: 修复线索清洗规则，新增去重逻辑"
# 查看历史版本
git log prompt_library/01_线索清洗智能体/prompt.md
# 回滚到历史版本
git checkout <commit_hash> -- prompt_library/01_线索清洗智能体/prompt.md
Commit 类型 说明 示例
feat 新增 Prompt feat: 新增线索清洗智能体 Prompt
fix 修复 Prompt 问题 fix: 修复招投标智能体废标项识别规则
refactor 重构 Prompt refactor: 优化输出格式说明
test 测试相关 test: 添加 A/B 测试记录

六、A/B 测试记录

在智能体目录下创建 test_records.md 记录测试结果：

# 测试记录

## 2026-07-20 招投标智能体 A/B 测试

测试版本
- 版本A：修改前（commit: abc123）
- 版本B：修改后（commit: def456）

测试数据
- 测试场景：10 份历史招标文件
- 测试结果：
  - 版本A准确率：85%
  - 版本B准确率：92%

结论
选择版本B上线，理由：废标项零遗漏

七、常见错误与修正

错误写法 正确写法 说明
"你要认真分析" "你要提取评分点、资格要求、废标条款" 要具体，不要模糊
"尽量准确" "准确率≥90%" 要量化，不要模糊
"看着办" "吃不准就标红交人" 要明确规则，不要自由发挥
"编一个合理的答案" "缺的直接标红，不许编" 禁止编造，诚实告知
没有异常处理 "找不到匹配案例：明确说无匹配，需人工提供" 必须有兜底策略

八、版本管理要求

项 要求
Prompt 文件 每个智能体只保留一个 prompt.md 文件
Git 管理 使用 Git 管理版本历史，每次修改都要提交 commit
Commit 规范 遵循 Git commit 规范（feat/fix/refactor/test）
A/B 测试记录 在 test_records.md 中记录测试结果
业务方签字 重大修改需要业务方确认，记录在 commit message 中
回滚机制 通过 Git 回滚到历史版本，Git log 可查看所有历史
