业务数据口径模板

FDE 阶段③ 交付物模板（通用）。用于把一个数据产品里每一个指标的取数出处、计算逻辑、去重/过滤/优先级规则一次性定死，作为阶段④建模、阶段⑤验收的对账依据。

适用形态：看板（实时 / 大屏指标）、报告（日 / 周 / 月 / 季 / 年周期汇总）、推送报告（阈值 / 告警 / 事件触发）。

核心要求：每个指标必须写清从哪个库、哪张表、哪些字段取数，并把信息科提供的 SQL 原样贴到「取数SQL」列——这是本交付物的价值所在，阶段④建模直接照此对齐物理表。

使用方法：删掉下面所有 示意 行，按本项目实际业务逐条填写。无法确定的口径 / 未拿到 SQL 的先置空、标记「待信息科提供」，不要编造表名或 SQL。

一、全局口径约定（本次交付统一遵循）

先把跨所有指标的通用规则定死，指标明细表里就不必逐条重复。按项目实际填写，用不到的整条删除。

数据集作用：数据集是一套可复用的业务数据资产，由取数SQL和最终输出字段组成，供看板、报告、推送和指标统一引用；数据集把客户物理库与业务指标隔离开，保证口径可复用、可追溯。

项目阶段：0–1 指新客户或新场景的首次交付，优先复制 SDR 标准库，客户存在额外数据库、字段或取数逻辑时新增数据集；1–2 指在已验证标品上的复制交付，直接复用 SDR 标准库数据集。两类项目都要登记数据集，并在“数据集类型”列标注“标准库”或“新增”。

数据源清单：本项目涉及哪些库 / schema（如 his、emr、埋点库 dwd），各自的连接方 / 责任人（信息科对接人），哪些必备、哪些可选。

命名与血缘：明细表「数据来源表」列统一写成 库.表(关键字段)，多表 join 的写主表并在「取数SQL」列体现关联；确保每个指标可追溯到物理字段。

过滤逻辑：全局默认过滤掉哪些数据（如：测试数据、status 无效、软删除 is_deleted=1、低于某等级）。

去重逻辑：同一实体多条记录时按什么唯一键去重、保留哪一条（最新 / 最早 / 优先级最高）。

优先级 / 归并：同一实体在多源命中或多条记录合并时，以哪一条为准。

时间口径：统计周期按什么时间字段切（创建时间 / 发生时间 / 完成时间），时区与截断到日/时的规则。

单位与精度：金额单位、百分比小数位、计数是否含 0 等展示口径。

标记约定：模型自动生成的内容与需人工补全的内容各用什么方式标记（如生成标绿、待补标紫），交付前待补项须清零。

二、数据集处理方式

数据集优先从 SDR 标准库复制。所有项目都要在数据集清单中登记使用的数据集；客户存在额外数据库、字段或取数逻辑时，在标准库基础上新增数据集或扩展数据集。

2.1 项目阶段与数据集策略

所有项目均需填写数据集清单，并在“数据集类型”列明确标注“标准库”或“新增”。新增数据库、字段或取数SQL时，才需要补充新增数据集的字段明细。

字段编码：使用英文小写加下划线，例如 order_amount；禁止同义字段重复命名。

填写约定：

四、指标类型说明

基础指标：直接来源于配置或单表原始字段，无需二次计算（如客户名称、报告周期、接收人）。

衍生指标：需按「取数SQL」+「逻辑」二次计算得出（如活跃数、环比、平均住院日、DRG 入组率、触发阈值）。

五、填写与验收要求

每个指标必须写清「数据来源表」（库.表(字段)）与「取数SQL」；SQL 直接采用信息科提供的版本，参数用 :begin、:tid 等占位便于阶段④套用。

「示例」列填本项目真实样例值，供业务方核对，不留占位符。

数据集清单必须标明“标准库”或“新增”。标准库数据集需标注 SDR 版本；新增数据集需完成取数SQL、字段明细及指标引用的对账。

表中所有 示意、—…— 分隔行在交付前全部删除；未拿到 SQL / 待补的口径按全局约定标记，交付前清零。

阶段④按 SDR 标准库复制并适配数据集；新增内容按本表补充建设。阶段⑤同时验收标品复用内容和新增内容，并按指标逐项对账。
