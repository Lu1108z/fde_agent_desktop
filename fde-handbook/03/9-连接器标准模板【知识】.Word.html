连接器（Connector）配置规范

一、工具 vs 连接器

类型 定义 示例 配置复杂度
工具（Tool） 封装好的原子能力，开箱即用 查询工具、文档生成工具 低
连接器（Connector） 对接外部系统的桥接层 CRM连接器、HIS连接器 高

二、配置步骤

步骤 内容
步骤一：梳理数据需求 问业务专家："你干这个活，需要查哪些系统？"
步骤二：申请数据权限 向数据管理员申请访问权限
步骤三：编写接口调用代码 明确请求方法、参数、返回格式、错误码
步骤四：处理异常和超时 重试机制、超时设置、降级策略
步骤五：配置 MCP（可选） 使用 MCP 协议标准化连接
步骤六：测试连通性 测试连接、测试查询、测试性能

三、连接器配置检查表

  • 数据需求已梳理
  • 数据权限已申请
  • 接口调用代码已编写
  • 异常处理已实现
  • 重试机制已配置
  • 超时设置已配置
  • 测试脚本已编写
  • 连通性已测试

四、MCP 配置方法

MCP（Model Context Protocol）是标准化的协议，用于让 AI 模型与外部工具和数据源交互。

MCP 配置步骤：

  1. 安装 MCP 服务：npm install -g @modelcontextprotocol/cli
  2. 配置 MCP 服务器：创建 mcp_config.json 文件
  3. 编写 MCP 服务器：定义工具、实现工具调用
  4. 在智能体中使用 MCP：通过客户端调用或在 Prompt 中声明
  5. 测试 MCP 连接：验证工具列表、工具调用
对比项 传统 API MCP
协议标准 每个系统不同 统一标准协议
工具发现 需要手动文档 自动发现可用工具
类型安全 弱类型 强类型（JSON Schema）
错误处理 各系统不同 统一错误格式
调试能力 依赖日志 内置 Trace 机制

五、自定义连接器

自定义连接器通过 DataHub MCP APIHub 和纳米 Work 提供标准化接入接口，支持同步和流式输出两种调用模式。

5.1 DataHub MCP APIHub

DataHub MCP APIHub 是统一的 API 网关层，负责将外部数据源和服务以 MCP 协议标准化暴露给智能体。

接入步骤：

  1. 在 DataHub 控制台注册 API 服务，配置请求/响应 Schema
  2. 选择输出模式：同步（sync）或流式（stream）
  3. 配置鉴权方式（API Key / OAuth2 / 签名验证）
  4. 发布为 MCP Tool，智能体即可自动发现并调用
  5. 在监控面板查看调用量、延迟、错误率
能力 说明
标准化接入 通过 MCP 协议统一封装第三方 API，智能体无需关心底层差异
同步输出 适用于响应时间短的查询类接口，请求-响应一次性返回完整结果
流式输出 适用于大模型生成、长文本返回等场景，通过 SSE/WebSocket 实时推送分片数据
工具自动发现 已注册的 API 自动出现在智能体可用工具列表中
权限管控 基于 RBAC 控制智能体对不同 API 的访问范围

5.2 纳米 Work 标准化接入

纳米 Work 提供工作流和任务编排的标准化连接能力，将企业内部系统（OA、CRM、ERP等）统一纳管，对智能体暴露标准化接口。

接入步骤：

  1. 在纳米 Work 平台注册目标系统，配置连接参数
  2. 定义接口映射：将原系统接口映射为标准化 MCP Tool
  3. 配置输出模式：同步返回或流式推送
  4. 设置超时与重试策略
  5. 测试连通性并发布上线
能力 说明
系统纳管 将分散的企业内部系统统一接入管理
标准化接口 屏蔽底层系统差异，对智能体提供统一调用规范
同步调用 适用于即时查询类操作（如查询审批状态、获取用户信息）
流式调用 适用于批量数据导出、实时事件推送等长耗时场景
工作流编排 支持多系统串联调用，编排复杂业务流程

5.3 同步与流式输出对比

对比项 同步输出 流式输出
适用场景 短耗时查询、状态获取 大模型生成、批量数据、实时推送
响应方式 一次性返回完整结果 分片逐步推送（SSE/WebSocket）
超时风险 低（秒级响应） 需配置长连接保活
用户体验 等待后一次展示 实时渐进式展示
错误处理 标准 HTTP 状态码 需处理中断续传、心跳检测

六、验收标准

检查项 达标标准
接口能调通 能正常调用外部系统
异常处理到位 超时、失败、权限错误都有兜底
权限配置正确 智能体只能访问它该访问的数据
性能符合要求 响应时间在可接受范围内
有使用文档 接口说明、调用示例、错误码
